# 一、游戏概述

## 1.1 一句话讲清这游戏

一款 2D 回合制策略卡牌游戏。玩家选一个种族,在方格地图上探索、建设据点、召唤兵种,最后用回合制卡牌战斗攻下敌方据点获胜。

## 1.2 核心玩法循环

一局游戏围绕以下循环展开,单次循环约 2–3 个游戏回合:

1. 探索:每回合英雄在地图上最多移动 3 格,寻找资源矿、兵种营地、随机事件。
2. 经营:用获得的建材和金币升级据点,据点每升一级解锁一个等级的新兵种卡牌。
3. 召唤:花费金币从据点召唤兵种(增加卡牌数量),组建战斗卡组。
4. 战斗:走到兵种营地或敌方据点时进入回合制卡牌战斗。
5. 循环:战斗胜利获得资源和卡牌,回到第一步,直到打下敌方据点。

## 1.3 目标体验

* 策略成长感:从弱小起点一步步壮大,最终碾压对手。
* 选择博弈感:每回合只能做一件事(移动/升级/召唤),逼玩家权衡。
* 种族特色感:三个种族玩起来感受明显不同(数值不同、克制不同)。
* 单局可控:一局 20 回合以内结束,约 20-30 分钟,适合课堂演示。

## 1.4 玩家数与模式

* 单人对战 AI
* 一局 2 方对抗:玩家方 vs AI 方
* 玩家选 1 个种族,AI 随机或由玩家指定另一个种族

# 二、对局规则

## 2.1 对局流程

游戏开始时:

1. 玩家在主菜单选择"新建游戏"或"读取存档"。
2. 新游戏:选种族 → 选 AI 对手种族 → 进入地图。
3. 地图生成完毕后,双方据点位于地图对角(玩家在左下,AI 在右上)。

## 2.2 回合规则

采用交替回合制,一个"大回合"(1天)由以下阶段组成:

1. 玩家回合:玩家可执行一个主操作(移动 / 升级据点 / 召唤兵种)+ 任意次免费操作(查看信息、整理卡组)。
2. AI 回合:AI 自动执行操作,画面播放简单动画。
3. 日结阶段:双方据点被动产出资源(金币 + 建材)。回合数 +1。

重点规则说明:

* 玩家回合每回合只能做一件"主操作",这是策略性的核心。
* 移动是主操作:点击目标格,英雄最多走 3 步(曼哈顿距离)。
* 升级据点是主操作:消耗资源,据点等级+1。
* 召唤兵种是主操作:消耗金币和建材,指定卡牌数量+1。

## 2.3 胜利条件

* 直接胜利:玩家英雄走到敌方据点上,并在卡牌战斗中打败守卫。
* 直接失败:敌方英雄走到我方据点上,并打下。
* 超时判定:20 回合结束仍未分胜负时,按"战力总值 + 资源总和"计算,低者判负。

战力总值计算公式(所有存活兵种的):

战力 = Σ(单卡攻击力 × 卡牌数量) + Σ(单卡血量 × 卡牌数量)

# 三、种族设计

## 3.1 三族三角克制

游戏只做 3 个种族,形成"石头剪刀布"式的克制三角:

* 人族 克制 天堂族
* 天堂族 克制 鬼族
* 鬼族 克制 人族

克制效果(全等级通用):

* 克制方:攻击力 ×1.2,受到伤害 ×0.8
* 被克制方:攻击力 ×0.8,受到伤害 ×1.2
* 非克制关系:无修正

## 3.2 种族差异化

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **种族** | **数值修正** | **升级成本** | **召唤成本** | **玩法定位** |
| 人族 | ×1.00 (基准) | 中 | 中 | 均衡稳健 |
| 天堂族 | ×1.10 (高) | 高 | 高 | 后期强势 |
| 鬼族 | ×0.95 (低) | 低 | 低 | 数量取胜 |

## 3.3 为什么只做 3 个种族

原版 5 个种族每个都要做立绘、UI 图标、建筑贴图、音效,美术工作量爆炸。3 个种族已能完美演示克制、数值差异、多态继承。如果 5 周内进度顺利,第 6 周可以加 1–2 个种族作为扩展。

# 四、地图与探索

## 4.1 地图规格

* 尺寸:10 × 10 方格
* 视角:2D 俯视(Top-down)
* 格子类型共 5 种

## 4.2 格子类型

|  |  |  |  |
| --- | --- | --- | --- |
| **类型** | **符号** | **数量** | **效果** |
| 空地 | · | 约 70 格 | 可以走过,无效果 |
| 资源矿 | R | 8 格 | 首次到达:获得 50 金币 或 50 建材(随机)。24 小时(1 回合)后刷新 |
| 兵种营地 | A | 6 格 | 战斗胜利后获得:3 张对应种族随机等级卡牌 |
| 随机事件 | E | 4 格 | 触发随机好事/坏事件。触发一次后变为空地 |
| 据点 | HOME/ENEMY | 各 1 格 | 双方起点,终局决战位置 |

## 4.3 地图生成规则

* 我方据点固定在 (0, 0),敌方据点固定在 (9, 9)
* 资源矿、兵种营地、随机事件在剩余格子中随机分布
* 生成规则:保证双方据点各自周围 3×3 范围内至少有 1 个资源矿 + 1 个兵种营地,避免开局饿死

## 4.4 英雄移动规则

* 每方有 1 个英雄,初始位于自家据点
* 每回合最多移动 3 格,按曼哈顿距离计算(|Δx|+|Δy| ≤ 3)
* 不能穿过敌方英雄所在格
* 走到格子上自动触发该格效果

## 4.5 随机事件表(好坏各 3 种)

|  |  |  |
| --- | --- | --- |
| **事件名** | **好/坏** | **效果** |
| 古代宝藏 | 好 | 获得 200 金币 |
| 流浪商人 | 好 | 获得 150 建材 |
| 英雄遇仙 | 好 | 获得 2 张 1 级本种族卡牌 |
| 强盗袭击 | 坏 | 损失 100 金币 |
| 沙尘暴 | 坏 | 本回合结束,下回合继续(跳过下回合主操作) |
| 瘟疫 | 坏 | 所有卡牌数量 -1(最少保留 1) |

# 六、卡牌系统

## 6.1 卡牌总览

每个种族 5 级,每级 1 种,共 3 种族 × 5 级 = 15 种基础卡牌。卡牌有"种类"和"数量"两个维度:种类决定等级和种族,数量代表该兵种的兵力。

## 6.2 卡牌基础数值(按原策划)

|  |  |  |  |
| --- | --- | --- | --- |
| **等级** | **单张攻击力** | **单张血量** | **对 1 级卡倍率** |
| 1 级 | 1 | 1 | ×1 (基准) |
| 2 级 | 3 | 3 | ×3 |
| 3 级 | 8 | 8 | ×8 |
| 4 级 | 16 | 16 | ×16 |
| 5 级 | 32 | 32 | ×32 |

## 6.3 种族修正

最终数值 = 基础数值 × 种族修正(然后再乘以克制系数):

* 人族:×1.00
* 天堂族:×1.10
* 鬼族:×0.95

## 6.4 召唤成本

|  |  |  |
| --- | --- | --- |
| **卡牌等级** | **基础金币** | **基础建材** |
| 1 级 | 20 | 10 |
| 2 级 | 60 | 30 |
| 3 级 | 150 | 80 |
| 4 级 | 400 | 200 |
| 5 级 | 1000 | 500 |

召唤要求:据点等级 ≥ 卡牌等级。不同种族再乘以种族成本系数。

## 6.5 战力计算示例

举例:5 张天堂族 2 级卡牌 vs 鬼族 2 级(天堂克鬼)

天堂方卡牌攻击力 = 3(基础) × 1.10(天堂) × 1.20(克制) × 5(数量) = 19.8

鬼族方卡牌血量 = 3(基础) × 0.95(鬼) × 1.20(被克制挨打更痛) × 5(数量) = ... 具体 debug 时再调

# 七、战斗系统

## 7.1 战斗触发

* 玩家英雄走到兵种营地 → 打怪战(vs 该营地守卫)
* 玩家英雄走到敌方据点 → 决战(vs 敌方全部卡组)
* 敌方英雄走到我方据点 → 防守战(vs AI)
* 敌我英雄相遇 → 遭遇战

## 7.2 战前准备

* 玩家从所有卡牌中选择最多 5 种作为出战卡组(原版是 7 种,简化为 5 种降低 UI 复杂度)
* 战斗中每种卡牌每回合可用 1 次,用完等下回合
* 双方可见对方的卡牌种类,但不可见具体数量

## 7.3 战斗流程(每大回合)

1. 本轮攻防身份:第一回合发起方为攻方,之后每回合互换。
2. 投降/逃跑判定:守方先问,攻方再问。选择投降或逃跑则立即结束战斗。
3. 出牌阶段(简化为明牌):攻方选 1 张卡出牌,守方随后选 1 张应战。
4. 结算伤害:

* 先结算种族克制,调整攻击力和受到的伤害
* 攻方卡牌对守方造成全额伤害
* 守方卡牌对攻方造成 50% 反击伤害

1. 扣血:按受到的总伤害,计算兵力损失数(= 伤害 / 单张血量,向下取整)。兵力=0 则卡牌阵亡。
2. 胜负检查:若一方全部卡牌阵亡 → 该方战败,战斗结束。否则进入下一大回合。

## 7.4 投降 / 逃跑惩罚

|  |  |  |
| --- | --- | --- |
| **时机** | **投降** | **逃跑** |
| 开局前 | 损 10% 金币 | 损 25% 金币 + 本回合不能再动 |
| 战斗中 | 已死的照死 + 损 10% 兵力 + 损 20% 金币(保底每种卡留 1) | 已死的照死 + 损 30% 兵力 + 损 40% 金币 + 50% 概率使一种低兵力卡阵亡 |

## 7.5 胜利奖励

* 打败营地守卫:获得 3 张该营地种族的随机等级卡牌
* 打败敌方英雄:获得对方 20% 的金币
* 打下敌方据点:游戏胜利

## 7.6 为什么简化为明牌

原版是"暗牌博弈"(双方同时背面出牌再翻),增加策略但需要同时出牌的 UI 设计、信息隐藏逻辑、可能的作弊防护。简化版采用明牌出牌,守方看到攻方出牌后再选应对,大大降低实现复杂度,同时依然保留"选哪张卡应对"的策略性。如果时间有余可以升级为暗牌。

# 八、AI 设计

## 8.1 设计原则

不使用机器学习、行为树或状态机等复杂 AI 技术。用简单的"优先级规则表",保证 AI 会打但不会太强。老师看到 AI 能正常动、会攻击、会发育就够分了。

## 8.2 AI 决策规则(每回合按此顺序判断)

1. 如果 建材和金币足够升级据点 且 据点等级 < 5:升级据点。
2. 否则,如果 金币足够召唤当前最高等级卡牌:召唤该卡牌。
3. 否则:英雄向玩家据点方向移动 3 格(A\* 或简单贪心路径)。
4. 移动过程中若踩到资源矿/兵种营地:自动触发对应效果。
5. 移动过程中若遇到玩家英雄:强制触发战斗。

## 8.3 AI 战斗策略

战斗中 AI 出牌规则:

* 进攻时:优先出当前最高等级卡牌
* 防守时:优先出克制对方来袭卡牌的种族卡(若有);若没有,出对方来袭同等级或更高级的卡
* 兵力低于 20% 总战力时:触发投降(而非逃跑)以保留种子兵力

## 8.4 难度设置(可选扩展)

* 简单:AI 初始资源正常,决策规则不变
* 困难:AI 初始资源翻倍,每回合日结产出 +50%

# 九、存档与读档

## 9.1 技术方案

使用 C# 的 JsonUtility 将游戏状态序列化为 JSON 文件,保存到 Application.persistentDataPath 路径下。这对应课程要求中的"文件处理"指标。

## 9.2 存档时机

* 菜单手动存档(覆盖当前存档)
* 每回合日结后自动存档(防止断电丢进度)
* 支持 3 个存档位

## 9.3 存档内容清单

SaveData 类需保存:

* 当前回合数、当前是谁的回合
* 玩家数据:种族、金币、建材、据点等级、卡组(每种卡的等级和数量)、英雄坐标
* AI 数据:同上
* 地图数据:每个格子的类型、是否被触发过、资源刷新计时
* 元数据:存档时间、游戏版本号

## 9.4 示例代码框架

[System.Serializable]
public class SaveData {
public int currentTurn;
public bool isPlayerTurn;
public PlayerSaveData playerData;
public PlayerSaveData aiData;
public TileSaveData[] tiles;
public string saveTime;
}
// 保存:
string json = JsonUtility.ToJson(saveData, true);
File.WriteAllText(Application.persistentDataPath + "/save1.json", json);
// 读取:
string json = File.ReadAllText(Application.persistentDataPath + "/save1.json");
SaveData data = JsonUtility.FromJson<SaveData>(json);

## 16.2 答辩可能的问题(提前准备答案)

* Q:你们哪里用了多态?→ A:Tile 基类的 OnHeroEnter 虚方法,每个子类重写
* Q:为什么这么设计类层级?→ A:用继承表达"是一种"关系(资源矿是一种格子),用组合表达"有一个"关系(玩家有一个卡组)
* Q:数据怎么保存的?→ A:JsonUtility 序列化,存在 Application.persistentDataPath
* Q:为什么选 Unity?→ A:C# 和 C++ 语法相近,可无缝迁移 OOP 思想;Unity 提供图形化场景和 UI,节省非核心代码时间
* Q:AI 是怎么实现的?→ A:优先级规则表,每回合按固定顺序判断
* Q:原策划 5 种族为什么只做 3 个?→ A:课设资源和时间约束下的工程权衡;3 族已完整演示克制系统和继承设计,扩展到 5 族只是工作量问题,不是架构问题
