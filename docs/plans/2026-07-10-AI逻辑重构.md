# AI 逻辑重构

Date: 2026-07-10

## Summary

重构 AI 控制器，使 AI 英雄具备与玩家 Hero 对等的能力（除兵营后台模拟完整战斗外），支持每回合最多 3 格移动、智能卡池策略、按总攻击力判断进攻时机。

## Changes

### 1. AI 多步移动 (AIController.cs)

- `FindPathToward(Vector2Int from, Vector2Int to)` — 新增方法，BFS 返回完整路径（`List<Vector2Int>`，不含起点），替代原来只返回下一步的 `FindNextStepToward`
- `MoveAIHeroToward(Vector2Int target)` — 重写：沿 BFS 路径走 `min(3, pathLen)` 步，`AIHero.MoveTo(最远可达位置)`，一次移动动画完成
- AI 移动逻辑：有一个"当前目的地"，每回合沿路径尽可能走 3 步；距离 ≤ 3 则走到目的地即停

### 2. AI 决策优先级重构 (AIController.cs — EasyAI / HardAI)

新的 `ExecuteTurn()` 决策优先级（从高到低）：

1. **免费行动**：升级据点 + 智能召唤 + 驻军管理（在己方据点时执行）
2. **检查目标是否失效**：如果当前目标格子已被清除（Cleared），清空目标重新搜索
3. **进攻模式**：总攻击力达标 → 目的地设为玩家据点，走最多 3 步
4. **收集资源**：找最近未清除资源点 → 走最多 3 步
5. **打兵营**：找最近未清除兵营 → 走最多 3 步
6. **探索事件**：找最近未清除事件格 → 走最多 3 步
7. **推进战线**：无目标时向玩家据点方向走 3 步（用尽移动力）

**进攻阈值（按总攻击力，即所有卡牌 baseAttack × quantity 之和）：**
- EasyAI：总攻击力 ≥ 90 → 进入进攻模式
- HardAI：总攻击力 ≥ 150 → 进入进攻模式
- 两者都不再使用距离限制，达标就冲

### 3. 智能召唤策略 (AIController.cs)

新增 `TrySmartSummon()` 替代原来的简单召唤：

- **多样性优先**：优先召唤卡组中还没有的兵种（`GetOwnedCount(unitIndex) == 0`）
- **高等级优先**：在可召唤范围内优先高等级单位
- **保留金储备**：至少保留 30 金币不花光
- EasyAI 每回合尝试召唤 1 次，HardAI 每回合尝试召唤 2 次
- 如果英雄卡组满槽（6 槽），自动将最低攻击力的重复卡牌转入驻军腾出空位

### 4. AI 卡组与驻军管理 (AIController.cs)

新增 `TryManageGarrison()`：
- 如果英雄卡组满槽且有更高级兵种可召唤 → 将最低攻击力的重复卡牌移入驻军
- 确保英雄携带的 6 槽是当前最强的组合

### 5. 兵营完整后台战斗模拟 (新增 AIBattleSimulator.cs)

新增 `AIBattleSimulator` 静态类，利用现有 `BattleManager` + `BattleAI` 进行完整后台战斗：

**流程：**
1. 根据当前回合数生成敌方卡组（后期兵营更强，随机种族 + 随机兵种）
2. 克隆 AI 当前卡组（不修改原始数据，用 `Card.Clone()`）
3. 创建 `BattleManager` 实例，`Initialize(aiDeck, enemyDeck)`
4. 双方均用 `BattleAI` 自动选择出牌/应战索引：
   - 攻方调用 `BattleAI.ChooseAttackerIndex()`
   - 守方调用 `BattleAI.ChooseDefenderIndex()`
5. 循环 `ExecuteRound()` 直到 `IsBattleOver()`
6. 根据 `outcome` 结算奖励/惩罚：
   - **AI 胜利**：获得敌方卡组中随机 1-2 张卡（通过 `TryAddToHeroDeck` 或 `AddToGarrison`），参与战斗的卡牌按剩余 HP 比例恢复
   - **AI 失败**：参战卡牌损失（根据战斗中实际阵亡情况），英雄撤退回原位置

**敌方兵营卡组生成规则：**
- 随机种族（Human/Heaven/Ghost）
- 卡牌数量 = 2 + turn/5（回合越后越多）
- 等级范围 = 1 ~ min(5, 1 + turn/4)
- 每张卡随机 unitIndex 和 level

### 6. 资源点/事件格保持不变

- 资源点和事件格的 AI 交互逻辑保持现有随机奖励/惩罚机制，不做改动

## Implementation Notes

- `Player` 需要新增 `GetTotalAttack()` 方法：`sum(card.baseAttack * card.quantity)`
- AI 的免费行动（升级、召唤）在移动**之前**执行
- 多步移动时，AI 只触发**最终到达格子**的 `OnAIEnterTile`，中间经过的格子不触发
- BFS 寻路允许目标格不可行走（如资源点），但中间格必须可通行
- 保留 `AIDifficulty` 枚举和 `InitializeAIController` 的动态切换支持
- 不修改 `GameManager` 的 AI 回合调度流程（`StartAITurn → ExecuteTurn → OnAIHeroArrived → EndAITurn`）
- HardAI 的 `currentTarget` 在到达后清空；如果目标被先清除（Cleared），重新搜索
- 后台战斗使用 `Card.Clone()` 克隆卡组，不影响 AI 原始数据，战斗结束后按结果回写
