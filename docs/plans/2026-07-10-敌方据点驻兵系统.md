# 敌方据点驻兵系统

Date: 2026-07-10

## Summary

敌方据点必须有驻兵防守。玩家攻击敌方据点时，需要同时对抗"AI 英雄卡组 + 敌方据点驻兵"的合并卡组。反之，AI 进攻玩家据点时，玩家也以"英雄卡组 + 据点驻兵"合并防守。

## Changes

### 1. 战斗卡组合并 (GameManager.cs)

**`StartEnemyStrongholdBattle(Vector2Int sourceTilePos)`** — 修改敌方卡组来源：
- 旧：`aiPlayer.deck.cards`（仅 AI 英雄卡组）
- 新：合并 `aiPlayer.deck.cards` + `aiPlayer.garrisonDeck.cards`

**`OnAIHeroEnterPlayerStronghold()`** — 修改防守方卡组：
- 旧：玩家仅以 `player.deck.cards` 防守
- 新：玩家以 `player.deck.cards` + `player.garrisonDeck.cards` 合并防守
- 进攻方仍为 `aiPlayer.deck.cards`（AI 英雄卡组）

合并逻辑：创建新 `List<Card>`，先 AddRange(heroDeck)，再 AddRange(garrisonDeck)，传入 `StartBattle()`。

### 2. 战后卡牌损失处理 (GameManager.cs)

强攻据点战败后，需要从正确的卡组中移除损失卡牌：

**新增 `RemoveCardsFromCombinedDeck(Deck heroDeck, Deck garrisonDeck, List<Card> battleCards)`**：
- 优先从 heroDeck 中移除参战卡牌（与现有 `RemoveCardsByBattleSnapshot` 逻辑相同）
- heroDeck 中找不到对应卡牌时，从 garrisonDeck 中移除

**修改 `ResolveEnemyStrongholdBattle(BattleOutcome)`**：
- 玩家战败时：从 `player.deck`（仅英雄卡组）移除损失卡牌
- 玩家胜利时：直接获胜（行为不变）

**修改 `ResolvePlayerStrongholdBattle(BattleOutcome)`**：
- 玩家防守失败（AI 攻破）：用 `RemoveCardsFromCombinedDeck` 从 `player.deck` + `player.garrisonDeck` 移除损失
- 玩家防守成功：行为不变

### 3. AI 初始驻兵 (GameManager.cs)

`StartGame()` 中，创建 aiPlayer 后，额外为 AI 据点添加初始驻兵：

```
aiPlayer.garrisonDeck.AddCard(CreateCardForRace(aiRace, 1, 2)); // Lv2 单位
aiPlayer.garrisonDeck.AddCard(CreateCardForRace(aiRace, 0, 1)); // Lv1 单位
```

玩家初始驻兵暂为 0（玩家可通过召唤和据点 UI 自行管理）。

### 4. AI 驻兵维护策略 (AIController.cs)

新增 `MaintainGarrison()` 方法，在 AI 免费行动阶段调用：
- 如果 `garrisonDeck.CardCount < 2`（驻兵不足）且资源充足 → 召唤 1 张卡牌直接加入 garrisonDeck
- 召唤后如果 garrisonDeck 仍为空（资源不足召唤）→ 从 heroDeck 转移 1 张最低攻击力的卡牌到 garrison
- 保证敌方据点始终至少有 1-2 张驻兵卡牌

### 5. 据点兵力 UI 提示 (StrongholdTile.cs / UIManager.cs)

敌方据点格子显示驻兵数量信息：
- `StrongholdTile.OnHeroEnter()` 在触发战斗前，通过 `MessageLogUI` 显示敌方驻兵数量：
  - "敌方据点：英雄 {heroDeckCount} 张 + 驻兵 {garrisonDeckCount} 张"
- 玩家据点同样显示己方驻兵数量

## Implementation Notes

- 合并后的卡组在 `PendingBattleState` 中统一存储，不区分来源。战后通过 `RemoveCardsFromCombinedDeck` 按 heroDeck → garrisonDeck 顺序移除
- AI 驻兵维护在 `ExecuteTurn()` 的免费行动阶段执行（升级 → 召唤英雄卡 → 维护驻兵）
- 初始 AI 驻兵数量不宜过多（2 张），避免前期玩家无法攻破
- 驻兵卡组 `garrisonDeck` 的 `hasSlotLimit = false`，无数量上限
- 不修改 BattleScene / BattleManager — 战斗系统已支持任意大小的敌方卡组
