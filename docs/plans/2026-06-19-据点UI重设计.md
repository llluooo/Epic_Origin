# 据点UI重设计 — 设计方案

**日期**: 2026-06-19
**功能**: 重写据点交互UI，召唤从随机改为可选+数量控制，据点操作不消耗回合行动

---

## 一、架构决定

| 决策 | 结论 |
|------|------|
| 布局方式 | 同一场景，双Camera切换（主相机↔据点相机） |
| 召唤方式 | 任何等级都可从可召唤兵种中自行选择（非随机） |
| 卡片展示 | 5张兵种卡牌并排，每张含卡牌美术图 + 数值 + 数量选择器 + 召唤按钮 |
| 卡组信息 | 融合到卡牌中：已有数量直接显示在每张卡牌上 |
| 离开交互 | 离开按钮 + Camera切换 |
| 行动消耗 | 据点操作（升级、召唤）完全不消耗回合行动 |

---

## 二、交互流程

```
英雄到达己方据点
      │
      ▼
主Camera disabled → 据点Camera enabled
      │
      ▼
  ┌─────────────────────────────────────────┐
  │  顶部：据点 LvN | 金币:XXX | 建材:XXX   │
  │  [升级据点] 消耗:XXX金 XXX材            │
  │                                         │
  │  Lv1卡  Lv2卡  Lv3卡  Lv4卡  Lv5卡     │
  │  (卡牌图+数值+[-][N][+]+[召唤])×5      │
  │                                         │
  │  [离开据点]                             │
  └─────────────────────────────────────────┘
      │
      ▼  （点击离开）
据点Camera disabled → 主Camera enabled → 回到地图
```

## 三、单张卡牌组件 (`UnitCardUI`)

```
┌────────────────────────────┐
│     [卡牌美术图]           │  ← race对应card png
│                            │
│  名称 LvN                 │  ← 兵种名 + 等级
│  ATK:N HP:N              │  ← 攻击/生命
│  消耗: N金 + N材          │  ← 单张召唤费用
│  拥有: ×N                │  ← 卡组中已有数量
│                            │
│  [-]    [N]    [+]        │  ← 数量选择器
│  [召唤 ×N] (总价:XX金)    │  ← 召唤按钮
└────────────────────────────┘
```

### 三种状态

| 状态 | 表现 | 触发条件 |
|------|------|----------|
| 锁定 | 灰色蒙版，按钮显示"需要据点LvN" | strongholdLevel < cardLevel |
| 资源不足 | 卡牌半透明，消耗数字变红，按钮灰色 | 等级够但总价超过现有资源 |
| 可召唤 | 正常亮色，可点击 | 等级够且资源够 |

### 数量选择器规则

- 默认数量: 1
- 最小: 1，最大: min(剩余资源÷单价的整数商, 99)
- 点击 +/- 增减1；输入框可直接键入
- 输入非法值（0、负数、超限、非数字）→ 自动回弹到最近的有效值
- 数量变化时 [召唤 ×N] 按钮上显示的总价实时更新

## 四、升级据点区

```
当前等级：Lv3
升级到 Lv4 → 消耗 400金 800材 [升级]
```
- 已满5级: 显示"已满级"，按钮隐藏
- 资源不足: 按钮灰色
- 升级成功: 刷新所有卡牌的可召唤状态（可能解锁Lv4卡牌）

## 八、边界情况

| 情况 | 处理 |
|------|------|
| 英雄点击敌方据点 | 走战斗逻辑，不切换相机 |
| 据点Lv1 | 仅Lv1兵种可召唤 |
| 资源刚好够 | 正常操作 |
| 连续快速点击召唤 | 0.5秒冷却防连点 |
| AI回合时进入据点 | 允许（据点操作不依赖回合） |
| 0张召唤 | 最小数量=1，不允许0 |
| 输入非法数字 | 自动修正到有效值 |
