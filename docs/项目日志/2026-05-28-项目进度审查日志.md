## 5. 重点代码审查发现

1. `Assets/Scripts/Core/GameManager.cs:125-140`  
   AI 回合没有任何决策，只是延迟后结束回合。策划案第 8 章要求 AI 按优先级升级、召唤、移动和触发战斗，这是当前完整闭环最大的缺口。

2. `Assets/Scripts/Map/ArmyCampTile.cs:10-25`  
   兵营战斗用随机战力 `10-50` 直接比较并发奖励，没有进入战斗系统；奖励是 1 张随机种族 Lv1-Lv2 卡 + 金币，也不符合“打败营地守卫获得 3 张该营地种族随机等级卡牌”的策划。

3. `Assets/Scripts/Map/ResourceTile.cs:5-20` 与 `Assets/Scripts/Map/EventTile.cs:6-17`  
   资源点和事件点没有触发状态。玩家可以反复进入同一资源/事件格刷收益或反复承受惩罚，与“首次到达触发、资源 1 回合刷新、事件触发后变为空地”的规则不一致。

4. `Assets/Scripts/Units/Card.cs:10-33` 与 `feature/rawBattleScene:Assets/Scripts/Units/Card.cs`  
   当前分支 `Card` 没有 `quantity`，战斗分支引入了 `quantity` 并按数量算战力。两条线合并前必须先统一卡牌数据模型，否则战斗分支直接合入会产生行为差异甚至编译冲突。

5. `Assets/Scripts/UI/StrongholdUI.cs:48-51` 与 `Assets/Scripts/UI/StrongholdUI.cs:97-107`  
   UI 显示和按钮可用性按“当前据点等级召唤成本”判断，但实际点击后是在 Lv1 到当前等级之间随机召唤。结果是：玩家可能明明买得起低级卡却按钮不可点；也可能 UI 显示的是高级卡费用，实际扣的是随机低级卡费用。

6. `Assets/Scripts/Units/Unit.cs:6-24` 与空目录 `Assets/Scripts/Race/`  
   已有 Unit 抽象基类和三族 Unit 派生类，Tile 多态也成立；但策划案要求的 Race 抽象基类与 HumanRace/HeavenRace/GhostRace 尚未实现。若课程硬指标按策划案答辩，需要补齐 Race 体系或在设计文档中说明改为 enum + 策略函数。
